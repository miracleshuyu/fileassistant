# 文件整理助手

一个基于大语言模型 Agent 的文件整理助手。

用户可以通过自然语言让 Agent 查看文件夹、读取文件、分析文件，并在用户确认后执行文件移动操作。

## 一、主要功能

### 1. 文件查看

使用 `list_files` 查看指定文件夹当前这一层的文件和子文件夹。

默认不会自动递归进入子文件夹。

### 2. 文件内容分析

使用 `read_file` 读取文本文件内容，让 Agent 根据文件内容辅助判断文件应该如何分类。

读取内容主要用于 Agent 内部分析，不主动向用户展示原文。

### 3. 文件移动

使用 `move_file` 将文件移动到指定分类文件夹。

文件移动具有权限控制：

* Agent 可以制定整理方案
* 用户确认整个方案后才能执行移动
* 用户没有输入“确定”时，程序禁止调用 `move_file`
* 一次“确定”授权当前完整整理方案
* 整理完成后自动撤销移动权限

### 4. 文件状态记忆

使用 `directory_tree` 保存文件夹的历史状态。

每次扫描后记录文件的：

* 文件路径
* 文件大小
* 所属文件夹结构

下一次检查同一个文件夹时，将当前状态与历史状态进行比较，可以发现：

* 新增文件
* 删除文件
* 文件大小发生变化
* 发生变化的文件夹

### 5. 增量扫描

目录状态记忆不仅用于发现变化，还用于减少重复扫描。

第一次检查：

```text
扫描整个目录
        ↓
保存目录状态
```

之后再次检查：

```text
检查当前目录状态
        ↓
与历史状态比较
        ↓
没有变化 → 直接使用历史记录
        ↓
发现变化 → 找到可能发生变化的子文件夹
        ↓
只重新扫描相关目录
```

因此，不需要每次都重新扫描整个目录。

如果多个子文件夹发生变化，则会分别找出这些发生变化的目录。

### 6. 多轮对话

程序支持连续多轮自然语言交互。

例如：

```text
用户：检查一下 D:\GitProjects

助手：发现 hello-git 发生了变化。

用户：再检查一次

助手：没有新的变化。

用户：看看 block-chess 能不能分类

助手：这个项目结构比较规整，不建议随意移动文件。

用户：exit

助手：好的，文件整理助手已结束，再见！
```

### 7. 程序退出

支持用户通过自然语言结束程序，例如：

exit
quit
退出

程序会直接退出，不需要调用大模型。

```text
fileassistant/

```

## 三、三个核心模块

### main.py

负责 Agent 主程序。

主要功能：

* 创建 DeepSeek 客户端
* 定义 Agent 可以调用的工具
* 管理多轮对话
* 调用工具
* 管理文件移动权限
* 处理用户输入
* 控制程序退出

---

### tools.py

负责定义 Agent 实际可以调用的工具。

目前主要包括：

```text
list_files
    ↓
查看当前文件夹

read_file
    ↓
读取文本文件

move_file
    ↓
移动文件

directory_tree
    ↓
检查目录状态、利用历史记录进行增量扫描
```

---

### directorytree.py

负责文件夹状态记忆。

主要工作：

```text
扫描文件夹
    ↓
建立目录状态
    ↓
保存历史记录
    ↓
下一次扫描
    ↓
与历史记录比较
    ↓
发现变化
    ↓
定位可能变化的文件夹
```

它本身不负责和用户进行对话，而是作为一个底层功能被 `directory_tree` Tool 调用。

# 四、数据流

文件整理功能的数据流：

```text
用户
 ↓
main.py
 ↓
Agent
 ↓
判断需要什么操作
 ↓
调用 Tool
 ↓
tools.py
 ↓
实际执行文件操作
 ↓
返回结果
 ↓
Agent
 ↓
向用户回答
```

目录状态记忆的数据流：

```text
用户要求检查文件夹
        ↓
Agent 调用 directory_tree
        ↓
directorytree.py
        ↓
读取历史状态 tree.json
        ↓
检查当前目录
        ↓
与历史状态比较
        ↓
判断是否发生变化
        ↓
定位变化的目录
        ↓
保存新的历史状态
        ↓
返回结果给 Agent
        ↓
Agent 向用户解释
```

# 五、权限流

文件查看和文件移动具有不同权限。

```text
用户请求查看
      ↓
Agent
      ↓
list_files / read_file
      ↓
直接执行
```

文件移动：

```text
用户要求整理
      ↓
Agent 分析文件
      ↓
生成整理方案
      ↓
询问用户确认
      ↓
用户输入“确定”
      ↓
程序授予 move_file 权限
      ↓
执行所有移动操作
      ↓
整理完成
      ↓
撤销 move_file 权限
```

核心原则：

> Agent 可以提出操作方案，但不能自行获得文件修改权限。

# 六、运行方法

首先创建虚拟环境：

```powershell
python -m venv .venv
```

进入虚拟环境：

```powershell
.\.venv\Scripts\Activate.ps1
```

安装依赖：

```powershell
pip install -r requirements.txt
```

设置 DeepSeek API Key：

```powershell
$env:DEEPSEEK_API_KEY="你的API Key"
```

运行：

```powershell
python main.py
```

# 七、项目特点

本项目重点不是简单实现“移动文件”，而是尝试解决 Agent 在文件操作场景中的两个问题：

### 1. 状态记忆

Agent 不应该每次面对同一个目录都从零开始检查。

通过保存目录状态，可以知道：

```text
之前是什么状态
        ↓
现在是什么状态
        ↓
哪里发生了变化
```

### 2. 权限控制

Agent 可以负责分析和制定方案，但涉及真实文件修改时，需要用户明确授权。

因此形成：

```text
Agent 决策
    ↓
用户确认
    ↓
程序授权
    ↓
执行操作
```

这也是本项目中 Agent 与实际文件系统之间的重要安全边界。
